# AI 变更自动调用规范

> 版本：v1.0 | 适用版本：v2.9.35+
> 目的：让AI在变更时自动调用工具，减少用户对命令行的依赖，实现"用户说需求 → AI自动走完整流程"。

## 一、变更触发场景识别

当用户表达以下意图时，AI必须识别为变更场景并启动自动流程：
- "改X"、"修改X"、"优化X"、"重构X"、"新增X"、"添加X"、"修复X"、"bug修复"
- "把X改成Y"、"X需要支持Y"、"X有问题"
- 任何涉及代码修改、功能新增、UI调整的请求

## 二、变更触发识别

### 2.1 变更触发关键词清单

以下用户表述属于变更触发，AI必须识别并启动自动流程：

**修改类**
- 改X、修改X、调整X
- 把X改成Y
- X需要改

**重构类**
- 重构X、重写X
- 拆分X、合并X

**优化类**
- 优化X、改进X、提升X
- X太慢、X不好用

**新增类**
- 新增X、添加X、增加X
- 加一个X、支持X

**删除类**
- 删除X、移除X、去掉X
- 不要X

**修复类**
- 修复X、修一下X
- X有bug、X有问题、X不对、X报错

**样式类**
- X颜色改一下
- X字号调大
- X布局调整

以下表述**不属于**变更触发：
- 纯咨询：X是什么、为什么X、X怎么用
- 纯查询：帮我查一下X、X的数据是多少
- 纯讨论：你觉得X怎么样、X和Y哪个好
- 纯解释：解释一下X、X的原理是什么

### 2.2 触发后的标准动作（6步）

1. 自动调用 `change-workflow.mjs start 1` 启动流程（阶段1 Brainstorming）
2. 自动分析影响范围（遍历神经网络 function_graph.json 中涉及节点的下游边）
3. 如果涉及UI变更（.vue/.css/.scss文件），自动调用 `ui-design-guide.mjs` 输出设计命令
4. 自动进入Brainstorming阶段，向用户确认需求细节（苏格拉底式提问）
5. 每个阶段完成后自动调用 `change-workflow.mjs complete <阶段号>` 更新状态
6. 变更完成后自动调用 `change-workflow.mjs complete 7` 完成流程

### 2.3 异常处理规则

- **工具调用失败**：记录错误但不阻断流程，向用户说明失败原因
- **用户中途改变需求**：自动重启变更流程（reset后重新start）
- **用户说"算了/不做了/取消"**：自动终止变更流程（调用reset）
- **涉及超过5个文件的大变更**：提醒用户确认后再执行
- **检测到P0 UI问题**：必须在变更中修复或明确记录豁免

### 2.4 自动触发合规性自检清单

AI在每次变更时必须自检以下10项：

1. 是否识别触发（用户表述是否属于变更触发关键词）
2. 是否启动流程（是否调用 change-workflow.mjs start 1）
3. 是否分析影响（是否遍历神经网络下游边分析影响范围）
4. 是否调用设计指导（UI变更是否调用 ui-design-guide.mjs）
5. 是否逐阶段更新（每阶段完成是否调用 complete）
6. 是否完成后finish（是否调用 complete 7 完成流程）
7. 是否记录变更历史（是否更新 change_history.json）
8. 是否升级版本号（是否同步升级版本）
9. 是否运行构建验证（是否运行 npm run build 并检查结果）
10. 是否处理异常（工具失败/需求变更/用户取消是否正确处理）

## 三、7阶段自动调用流程

### 阶段1：变更启动（Brainstorming）
**触发**：识别到变更场景后立即执行
**自动调用**：
```bash
node scripts/change-workflow.mjs start --title "<变更标题>" --type "<feature|bugfix|refactor|optimization>" --priority "<P0|P1|P2|P3>"
```
**AI动作**：
- 苏格拉底式7问分析需求
- 替代方案对比
- 输出变更方案摘要

### 阶段2：任务分解（WritingPlans）
**触发**：阶段1完成后
**自动调用**：
```bash
node scripts/change-workflow.mjs update --stage "writing-plans" --status "completed"
```
**AI动作**：
- 任务分解到2-5分钟粒度
- 文件路径精确到行
- YAGNI/DRY检查

### 阶段3：UI设计指导（仅UI变更时）
**触发**：变更涉及UI（.vue/.css/.scss文件）
**自动调用**：
```bash
node scripts/ui-design-guide.mjs --files "<变更文件列表>"
```
**AI动作**：
- 阅读输出的设计命令
- 在编码时遵循impeccable 23条设计原则

### 阶段4：编码实现（SubagentDev）
**触发**：任务分解完成后
**自动调用**：每个子任务完成后
```bash
node scripts/change-workflow.mjs update --stage "subagent-dev" --status "in-progress" --note "<当前子任务>"
```
**AI动作**：
- 逐任务实现并验证
- 含中文文件必须用Python脚本修改（encoding='utf-8'）

### 阶段5：UI变更检测（仅UI变更时）
**触发**：UI编码完成后
**自动调用**：
```bash
node scripts/change-ui-check.mjs
```
**AI动作**：
- 阅读检测结果
- P0问题必须修复或记录豁免
- 检测结果记录到变更历史

### 阶段6：构建与验证（Verification）
**触发**：编码完成后
**自动调用**：
```bash
npm run build
```
（prebuild钩子自动运行UI检测+测试检查+验证清单，postbuild钩子自动运行构建后验证）
**AI动作**：
- 阅读prebuild和postbuild输出
- 验证失败项必须处理或记录豁免
- 运行 `node scripts/change-workflow.mjs update --stage "verification" --status "completed"`

### 阶段7：完成收尾（Finishing）
**触发**：验证通过后
**自动调用**：
```bash
node scripts/change-workflow.mjs finish
```
**AI动作**：
- 更新change_history.json
- 升级版本号
- 同步神经网络（涉及节点的version和last_verified）
- 打包部署

## 四、工具调用参数规范

### change-workflow.mjs
| 命令 | 参数 | 说明 |
|------|------|------|
| start | --title, --type, --priority | 启动新变更流程 |
| update | --stage, --status, --note | 更新阶段状态 |
| finish | 无 | 完成变更流程 |
| status | 无 | 查看当前流程状态 |

### ui-design-guide.mjs
| 参数 | 说明 |
|------|------|
| --files | 变更的.vue文件列表，逗号分隔 |
| --scenario | 场景：new-component/refactor/layout/performance |

### change-ui-check.mjs
无参数，自动检测最近变更的UI文件。

### postbuild-verification.mjs
无参数，由postbuild钩子自动调用。

## 五、异常处理

### 工具调用失败
1. **脚本不存在**：检查scripts目录，确认文件名拼写。如果脚本确实不存在，记录到变更历史并继续（不要阻塞流程）。
2. **脚本执行报错**：阅读错误信息，尝试修复。如果是脚本本身的bug，记录到known_issues，用手动方式完成等效操作。
3. **退出码非0**：区分"验证发现问题"（正常，需要处理问题）和"脚本执行失败"（异常，需要修复脚本）。

### 文件不存在
1. `.ui-check/latest-merged.json` 不存在：显示空状态，不报错。
2. `change-workflow` 状态文件不存在：说明没有进行中的变更，显示空状态。
3. `docs/impeccable-design-commands.md` 不存在：设计命令参考显示空状态。

### 网络/构建错误
1. npm install失败：检查网络，重试。如果持续失败，使用已有的node_modules。
2. 构建失败：阅读错误信息，定位到具体文件和行，修复后重新构建。
3. 后端启动失败：检查端口占用，查看日志。

## 六、结果汇报规范

### 变更进度汇报
每个阶段完成后，向用户简要汇报：
- 当前阶段：XXX
- 完成情况：通过/失败/有警告
- 关键发现：（如果有）
- 下一步：XXX

### 变更完成汇报
变更完成后，提供完整执行报告：
1. 变更标题和类型
2. 7阶段完成情况（表格）
3. 修改的文件列表
4. UI检测结果（P0/P1/P2/P3数量）
5. 构建验证结果
6. 版本号变更
7. 已知问题和后续建议

## 七、Live检测自动触发机制（方案三：两者结合）

### 7.1 变更类型判断标准

AI在处理UI变更需求时，必须先判断变更类型，再选择对应的检测触发方式。

#### 简单UI变更

**判断标准**（同时满足）：
- 修改1-3个UI文件
- 不涉及组件结构重构
- 典型场景：调整颜色、修改字号、调整间距、修改单个组件样式

**触发方式**：AI改完每个UI文件后，自动调用 `change-ui-check.mjs <文件路径>` 检测该文件。

**反馈方式**：检测结果直接在对话中反馈给用户。

**处理规则**：
- P0问题必须当场修复
- P1/P2问题告知用户并建议修复
- P3问题可记录到后续迭代

#### 复杂UI变更

**判断标准**（满足任一）：
- 修改4个以上UI文件
- 涉及组件结构重构
- 涉及页面布局重构

**触发方式**：AI在开始变更前，自动在后台启动 `ui-live-watch.mjs`（通过 `ui-live-auto.mjs start`）。

**运行方式**：后台进程持续监听文件变化，自动检测，无需AI逐文件调用。

**反馈方式**：AI定期（每完成一个阶段或每修改3-5个文件）汇总检测结果反馈给用户（通过 `ui-live-auto.mjs summary`）。

**结束方式**：变更完成后，AI自动停止后台监听进程（通过 `ui-live-auto.mjs stop`）。

### 7.2 AI自动调用流程（6步）

```
用户提需求
    │
    ▼
1. AI判断变更类型（简单/复杂）
    │
    ├── 简单变更 ──→ 2a. 逐文件修改，每改完一个自动调用 change-ui-check.mjs 检测
    │                    │
    │                    ▼
    │                 3a. P0问题当场修复，P1/P2告知用户
    │
    └── 复杂变更 ──→ 2b. 自动后台启动 ui-live-watch.mjs
                         │
                         ▼
                      3b. 持续监听，定期汇总反馈（每阶段或每3-5个文件）
                         │
                         ▼
                      4b. P0问题当场修复
                         │
                         ▼
                      5b. 变更完成后自动停止后台监听
    │
    ▼
6. 汇总所有检测结果，向用户完整反馈
```

### 7.3 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 检测脚本调用失败 | 记录错误信息，不阻断变更流程，向用户说明失败原因 |
| 后台监听意外退出 | 自动重启一次；若重启失败，切换为简单模式（逐文件调用change-ui-check.mjs） |
| 检测到超过10个问题 | 暂停变更，向用户汇报问题清单，等待用户指示后继续 |
| 判断类型不确定 | 按复杂变更处理（启动后台监听），确保不遗漏检测 |
| 用户中途取消 | 复杂变更需先停止后台监听，再终止变更流程 |

### 7.4 用户零操作声明

**用户不需要做任何操作**：
- 不需要运行 `npm run ui:watch`
- 不需要手动启动/停止检测脚本
- 不需要查看终端输出
- 只需要说需求，然后看AI反馈的检测结果

所有检测脚本的启动、运行、停止、结果汇总均由AI自动完成。

### 禁止事项
- 不要让用户手动运行命令行脚本
- 不要跳过变更准入网关直接改代码
- 不要在验证失败时声称"已完成"
- 不要用PowerShell Set-Content修改含中文文件
